# Security Policy

## Supported Versions

Security fixes are applied to the current `main` branch and the most recent release. Older releases are not normally
patched.

## Reporting A Vulnerability

Use the repository's private vulnerability reporting channel from its **Security** tab. Include the affected version,
steps to reproduce, impact, and any proof of concept needed to evaluate the report. Do not include credentials,
customer data, or private keys.

If private reporting has not been enabled, open a minimal public issue asking a repository owner for a private contact.
Do not disclose the vulnerability details in that issue.

Maintainers aim to acknowledge valid reports within seven calendar days, assess the impact, and coordinate a fix and
disclosure timeline with the reporter. Please allow a fix to be released before publicly disclosing an issue.

## Scope

Report vulnerabilities in Envoy source code, the published container configuration, default deployment guidance, and
first-party GitHub automation. Provider accounts and third-party services should be reported to their respective
security teams when the issue is outside Envoy's control.
